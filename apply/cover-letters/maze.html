Dear Maze team,

When an AI agent takes action inside a security workflow, the hard problem isn't detection - it's accountability. Someone still has to see what the agent did, judge whether to trust it, and answer for the decision. In a domain where a wrong automated call has real consequences, the interface isn't a report of the agent's work; it's the place a human stays in control of it. That's a design problem before it's a model problem - and it's made in real code, at the seam where design decisions actually get built.

That seam is where I work. I'm a designer with 13 years of craft who ships in code - React, Tailwind, Astro - and takes an idea to a working, accessible interface myself, rather than handing off a screen. The clearest proof is the Article 50 UI Pattern Kit: an open-source (MIT) React component library I designed and built for EU AI Act transparency, four WCAG 2.1 AA components with a passing axe audit, live with a working demo (github.com/sotosili/article50-kit). Its core is Maze's problem in miniature - an AI that streams its reasoning, shows a real confidence signal, and hands the decision to a person when it's unsure: approve, override, or reject. The agent acts; a human still answers for it. Making that loop legible at a glance is exactly the craft that data-dense security work demands.

Maze is defining what product design looks like for AI agents in a space where the patterns don't exist yet - and treating design as the thing that makes the whole system trustworthy, not a finish applied at the end. That's the work I most want to do: the human-accountable layer of an AI product, built in real code with a genuine point of view about keeping a person in the loop. I would love to talk.
