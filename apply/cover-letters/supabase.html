Dear Supabase team,

For a developer tool, the interface is the argument. The dashboard, the docs, the first five minutes - that's where a team decides whether to trust you with their data, and no amount of backend quality wins it back if the surface feels clumsy. Design engineering, the seam where design decisions get made in real code, is where that argument is won.

That seam is where I live. I'm a designer with 13 years of craft who ships in code - React, Tailwind, Astro, on the open-source stack Supabase is built for. I don't hand off screens; I take an idea to a working, accessible interface myself. And I build in the open: the clearest proof is the Article 50 UI Pattern Kit, an open-source (MIT) React component library I designed and built for EU AI Act transparency - four WCAG 2.1 AA components with a passing axe audit, on GitHub and running live with a working demo (github.com/sotosili/article50-kit). It's a whole small product taken from problem to shipped, documented, adoptable code - which is the shape of the work a design engineer does every day.

Supabase is one of the few companies where "open-source" is a value, not a line in a README - and where a designer who can actually build is treated as an engineer, not a decorator. That's the environment I do my best work in. I'd love to bring the craft-plus-code combination to the surface your developers touch first. I would love to talk.
